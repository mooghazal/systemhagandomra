# نظام إدارة الحج والعمرة — Hagamra

نظام متعدد الشركات لإدارة باقات الحج والعمرة والفنادق والحافلات والموظفين.

```
hagamra/
├── backend/             Laravel 13 + MySQL — الواجهة البرمجية ومنطق العمل
├── packages/shared/     المكوّنات وعميل API والشاشات المشتركة بين اللوحتين
├── admin-panel/         Next.js — لوحة المشرف العام        (منفذ 3000)
├── company-dashboard/   Next.js — لوحة الشركة              (منفذ 3001)
├── mcp-server/          خادم MCP للوكيل الذكي
└── tools/               composer.phar
```

التطبيقان مساحة عمل npm واحدة. ~٨٠٪ من كودهما في `packages/shared` — المكوّنات
وعميل API والأنواع وشاشات الباقات والفنادق والحافلات والموظفين — فإصلاح خطأ
يحدث مرة واحدة. ما يخصّ كل لوحة وحدها: قائمتها وهويتها ومسارات صفحاتها.

## المعمارية

```
            ┌──────────────────┐
            │  لوحة التحكم     │  Next.js
            │  admin-panel     │
            └────────┬─────────┘
                     │  كوكي httpOnly → وسيط Next → Bearer token
                     ▼
            ┌──────────────────┐
            │  Laravel Backend │  المصادقة · الصلاحيات · عزل الشركات
            │                  │  التحقق · منطق العمل · سجل التدقيق
            └────────┬─────────┘
                     ▼
                 ┌───────┐
                 │ MySQL │
                 └───────┘
```

**Laravel هو السلطة الوحيدة.** لوحة التحكم لا تتصل بقاعدة البيانات، ولا تتخذ قرار صلاحية.
إخفاء زرّ في الواجهة ليس حماية — الخادم يرفض الطلب في كل الأحوال.

## التشغيل

### المتطلبات

| | الإصدار المستخدم هنا |
|---|---|
| PHP | 8.3 (pdo_mysql, gd, fileinfo, intl) |
| MySQL | 8.0 — **8.0.16+ ضروري** لقيود CHECK والأعمدة المولّدة |
| Node | 22 |

### ١. قاعدة البيانات

```bash
mysql -u root -p < backend/database/setup-mysql.sql
```

ينشئ قاعدتَي `hagamra` و`hagamra_test` ومستخدماً مخصّصاً. كلمة المرور مولّدة داخل
الملف ومطابقة لـ`backend/.env`. **احذف الملف بعد تشغيله** — فهو يحوي بيانات اعتماد حيّة.

> إن تعذّر الدخول بـroot، هناك طريق لا يحتاج كلمة مروره في
> `backend/database/mysql-init.sql` عبر `mysqld --init-file`.

### ٢. الباك إند

```bash
cd backend && php ../tools/composer.phar install && php artisan migrate --seed && php artisan storage:link
```

`storage:link` ضروري وإلا لن تُعرض الصور المرفوعة.

### ٣. الواجهتان

من جذر المشروع — مساحة عمل واحدة تُثبّت الاثنتين والحزمة المشتركة معاً:

```bash
npm install
```

```bash
cp admin-panel/.env.example admin-panel/.env.local && cp company-dashboard/.env.example company-dashboard/.env.local
```

### ٤. التشغيل

ثلاث نوافذ:

```bash
cd backend && php artisan serve --port=8000
```

```bash
cd admin-panel && npm run dev
```

```bash
cd company-dashboard && npm run dev
```

لوحة المشرف على `http://localhost:3000`، ولوحة الشركة على `http://localhost:3001`.

## الحسابات

كلمة مرور المشرف العام في `backend/.env` تحت `SUPER_ADMIN_PASSWORD`.
**غيّرها قبل أي استخدام حقيقي.**

بيانات تجريبية (تطوير فقط — يرفض التشغيل في الإنتاج):

```bash
cd backend && php artisan db:seed --class=DemoDataSeeder
```

| الحساب | الدور |
|---|---|
| `owner@alnoor.example` | مالك شركة |
| `manager.employee@alnoor.example` | موظف بكل الصلاحيات |
| `sales.employee@alnoor.example` | باقات فقط |
| `viewer.employee@alnoor.example` | قراءة فقط |
| `nobody.employee@alnoor.example` | بلا صلاحيات |

كلمة المرور للجميع: `demo-password-123`

تُنشأ شركتان عمداً — سلوك العزل بين الشركات لا يمكن التحقق منه بشركة واحدة.

## الاختبارات

```bash

```

```bash

```


## الأمان — الخلاصة

التفاصيل في [backend/docs/SECURITY.md](backend/docs/SECURITY.md).

**عزل الشركات أربع طبقات مستقلة:** نطاق استعلام عام، وربط مسارات يُرجع **404 لا 403**
(الـ403 يؤكّد وجود السجل)، وسياسات تفحص `company_id` من جديد، و`company_id` غير قابل
للتعبئة الجماعية إطلاقاً.

**منع التصعيد:** موظف يملك `employees.update` يعدّل زملاءه لكن **لا يمنح صلاحيات** —
وإلا لتحوّلت صلاحية واحدة إلى الستّ عشرة. دور `owner` يُسنَد في مكان واحد فقط.

**الرمز في كوكي httpOnly** لا تراه جافاسكربت، فثغرة XSS لا تسرقه.

## الواجهة البرمجية

التوثيق الكامل في [backend/docs/API.md](backend/docs/API.md).

قاعدة تستحق الانتباه: **الحقل المحذوف يبقى كما هو، والحقل المُرسَل `null` يُمسح،
و`0` و`false` و`[]` تُحفظ كما هي.** هذا ما يسمح بتعديل خاصية واحدة دون إعادة إرسال
الباقي — أو تخمينه.

لغة رسائل التحقق تتبع ترويسة `Accept-Language` (عربي/إنجليزي)، فالخادم يخدم
لوحة عربية ووكيلاً ذكياً يقرأ مخرجاته مطوّر.

## الوكيل الذكي (MCP)

```bash
cd backend && php artisan mcp:token owner@example.com
```

ثم في `mcp-server`: `npm install && npm run build`. التفاصيل في
[mcp-server/README.md](mcp-server/README.md).

**نموذج الأمان بنيوي لا إجرائي:** الخادم يحمل رمزاً واحداً لحساب واحد ويتحدث HTTP
إلى Laravel. لا اتصال بقاعدة بيانات، ولا بيانات اعتماد ثانية، ولا مسار مميّز. كل ما
يستطيعه هو ما يستطيعه ذلك الحساب لو سجّل الدخول من المتصفح — لا أكثر. فـMCP **باب،
لا حارس**.

وكل عملية يُسجّلها التدقيق بمصدر `mcp_agent`، تميّزها عن `dashboard`.

## ملاحظات تشغيلية

- `backend/.env` و`database/setup-mysql.sql` و`mysql-init.sql` في `.gitignore` — لا تُرفع.
- في الإنتاج: `APP_DEBUG=false`، و`COOKIE_SECURE=1`، وHTTPS، وضبط
  `FRONTEND_ADMIN_URL`/`FRONTEND_COMPANY_URL`.
- **أبقِ نطاقَين في CORS على الأقل.** مكتبة php-cors تختصر عندما يكون المسموح نطاقاً
  واحداً فترسله لكل طالب مهما كان مصدره — يبقى آمناً لأن المتصفح يقارن ويحجب، لكنه سلوك مفاجئ.
- حذف الشركة حذف ناعم يتتالى يدوياً داخل `CompanyService` — قيود قاعدة البيانات
  لا تراه، فلولا ذلك لظلّ موظفوها يسجّلون الدخول.

## ملاحظة على كوكي الجلسة

المتصفّحات تربط الكوكيز بالمضيف وتتجاهل المنفذ، فلوحتان على `localhost`
تتشاركان جرّة كوكيز واحدة — ولولا تدبير لكان الدخول إلى إحداهما يسلّم جلستها
للأخرى. لذلك تسمّي كل لوحة كوكيها عبر `SESSION_COOKIE_NAME` في `.env.local`.
في الإنتاج يجلسان على نطاقين مختلفين فلا يتصادمان أصلاً، لكن اتركها مضبوطة.
